# Lab 1.6 — Reflection

I extended the Gemini unit test generator with retrieval from ChromaDB. The collection contained 1,000 synthetic C# and xUnit pairs across four rule families. For the new input, ChromaDB retrieved `stock-091`, `stock-103`, and `stock-108` using cosine distance over embeddings of X. Both runs used the same Gemini model and `OrderQuantityValidator` input. The run without RAG generated 10 cases and covered five of the six selected scenarios, while the RAG run generated nine cases and covered all six. The RAG output included a separate test that expects an order of 10 items to be allowed when 15 are in stock. The output without RAG also included a negative-stock case. I compared the generated code by inspection. Running both suites with `dotnet test` and measuring code coverage would provide a stronger comparison.
